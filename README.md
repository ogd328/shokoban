# 書庫番（Shokoban）

[English](README.en.md)

打ち合わせの文字起こしを**手元の PC の中だけで伏せ**、**人が全文を確かめ**、確かめた中身だけから**進行メモ**を作る道具です。
「打ち合わせを細かく覚えていなくても、後で全部たどれる」ことを目指しています。

> まだ若いソフトです（0.1）。作者が自分の仕事で毎日使いながら育てています。**日本語の打ち合わせ専用**で、**動くのは macOS だけ**です（下の「動く環境」を見てください）。足りない所は「既知の制約」に正直に書きました。改善を歓迎します。

## 何をするか

```
文字起こし ──▶ ① 伏せる（決まり＋名前の辞書＋手元AI＋GiNZA） ──▶ ② 名前の確認（人）
          ──▶ ③ 送る前の確認（人が伏せたあとの全文を読む） ──▶ ④ 読む役が進行メモを作る
          ──▶ ⑤ 人が直して保存 ──▶ ⑥ 共有フォルダへ（ほかの道具・エージェントが読む）
```

できあがる進行メモの欄（画面では、もとの5つの欄にちなんで「5欄」と呼びます。今は道筋の欄を足した6つです）:

- こちらから話した道筋・提案
- 困りごと
- 頼まれていること
- こちらがやること
- 決まったこと
- まだ決まっていないこと

各行には、誰が話したか（お客様／こちら）の印が付きます。

## 外に出さないための決まり

- 文字起こし・お客様の名前・伏せる前の文は、**この PC の外に出しません**。
- 読む役（④）に渡すのは、**人が③で全文を読んで「確認済み」にした、伏せたあとの文だけ**です。送る直前に中身の指紋（sha256）を照らし、確認したものと1文字でも違えば送りません。
- 読む役は既定で**止まっています**（環境変数で有効にするまで、何も外へ出ません）。
- 保存するファイルは 0600、フォルダは 0700 で作ります。

### 伏せる仕組みと、その限界

- 伏せる処理の中心は**決まり（正規表現と語の一覧）**です。手元AIは、名前の候補を探すことと、伏せた区間に短い札を付けることに使います。GiNZA（任意）は名前の候補を増やします。
- 置き換える札は、〈名前〉〈社名〉〈連絡先〉〈金額：幅〉〈数字〉〈体調の事情〉〈家族の事情〉などと、文まるごとの〈この文は伏せました〉です。
- 名前・社名は、決まりと手元AIが出した候補を**②の画面で人が1語ずつ決めます**。決めていない候補は、伏せたまま送ります。
- **地名・住所を専用に伏せる決まりはありません。** 業種や商品から相手が分かる、といった文脈からの推測も機械では防げません。
- ③の画面は、漏れていそうな文を目立たせますが、目立たせるのは全体の1割までです。**最後の関所は、③で人が全文を読むことです。** 気になる文はその場で「さらに伏せる」を選べます。

## 向いている打ち合わせ

指示文と語の一覧は、**小さなお店・事業者の Web・チラシ・SNS・写真などの制作や広報を手伝う側**が録音した打ち合わせに合わせて調整してあります（作者の仕事がそれだからです）。前提は次のとおりです。

- 録音したのは支援する側（こちら）で、話しているのはお客様とこちらの2者。
- 文字起こしに話者の印は要りません（誰が話したかは読む役が推し量ります）。文は「。！？」と改行で分けます。
- 日付・月の区切りは日本時間です。

ほかの業種や形の打ち合わせでも動きますが、拾い方が合わないことがあります。合わせる改善を歓迎します。

## 動く環境

- **macOS（Apple Silicon 推奨）**、Python 3.12 以上。
  - Linux では手元AIを起動できません（空きメモリの確かめに macOS の `memory_pressure` を使うため）。Windows では画面が立ち上がりません。
- [llama.cpp](https://github.com/ggml-org/llama.cpp) の `llama-server` と、日本語が得意な GGUF モデル（作者は Gemma 4 12B の日本語版を使用）。
  - **新しめの llama.cpp が要ります**（起動時に `--reasoning off` と `--no-webui` を渡します。作者は build 12110 で確認）。古い版だと起動に失敗し、画面には「120秒以内に応答しませんでした」とだけ出ます。
  - 書庫番が使う時だけ `127.0.0.1:1234` で起動します（**ポートは 1234 固定**）。LM Studio など、1234 を使うほかのソフトとは同時に使えません。
  - モデルは `runtime.json` の `models` に `gemma-4-12b-ja` という呼び名で登録します。別の呼び名にするときは `SHOKOBAN_TAGGER_MODEL` で指定します。
  - **モデルのファイルと `llama-server` の場所は、空白や日本語を含まないパス**にしてください（起動したプロセスを見分けるために必要です。含まれていると設定の時点で断ります）。
- 作業フォルダ（データの置き場所）は、自分だけが読める権限（`chmod 700`）で、Mac の内蔵ディスクなど権限の効く場所に置きます。
- （任意）GiNZA: 人名・社名の候補を増やします。本体とは別の venv に入れます。
- （任意）読む役: [Claude Code](https://docs.anthropic.com/en/docs/claude-code) の `claude` コマンド、または手元の OpenAI 互換サーバー（下の「読む役」）。

## はじめ方

```bash
git clone https://github.com/ogd328/shokoban.git && cd shokoban
python3.12 -m venv .venv && .venv/bin/pip install -e ".[dev]"
```

作業フォルダを作り、手元AIの設定を置きます。

```bash
mkdir -p ~/shokoban-data && chmod 700 ~/shokoban-data
cp examples/runtime.example.json ~/shokoban-data/runtime.json
# runtime.json の models（GGUF の絶対パス）と state_dir（絶対パス）を書き換える
```

`runtime.json` の項目: `ctx`（文脈の長さ）、`idle_minutes`（この分数使わなければ止めてよい）、`min_free_percent`（空きメモリがこの％未満なら起動しない）、`default_model`・`models`（呼び名と GGUF の絶対パス）、`state_dir`（起動の記録を置くフォルダ）。

（任意）GiNZA を作業フォルダの `venv-ginza` に入れます。

```bash
python3.12 -m venv ~/shokoban-data/venv-ginza
~/shokoban-data/venv-ginza/bin/pip install ginza ja_ginza
```

まず**架空データのモード**で画面を開きます。

```bash
SHOKOBAN_WORK_DIR=~/shokoban-data SHOKOBAN_DATA_MODE=synthetic \
  .venv/bin/streamlit run gui/shokoban_mac.py \
  --server.address 127.0.0.1 --browser.gatherUsageStats false
```

`--browser.gatherUsageStats false` は、Streamlit が利用統計を外へ送らないようにする指定です。

見本の文字起こしで試せます（架空データのモードでは、お客様名が「架空顧客」で始まるファイルだけを取り込みます）。

```bash
cp "examples/2030-01-15 架空顧客サンプル.txt" ~/shokoban-data/inbox/
```

（`inbox` フォルダは、画面を一度開くと作られます。）

本番のデータで使うときは `SHOKOBAN_DATA_MODE=real SHOKOBAN_REVIEW_REAL=1` にします（`SHOKOBAN_REVIEW_REAL=1` が無いと、名前の確認と送る前の確認が開きません）。架空と本番のデータは別のフォルダ（`store-synthetic/` と `store/`）に分かれます。

## 使い方の流れ

1. **文字起こしを置く**: `<作業フォルダ>/inbox/` に、`2026-01-15 お客様名.txt` の形の名前で置きます（半角の日付・半角スペース・お客様名。`.txt` か `.md`、UTF-8、5MB まで）。名前の部分が、そのままお客様の名前になります。
2. **取り込む**: 「案件一覧」→「受け取りフォルダを取り込む」。下書きの打ち合わせができ、元のファイルは `inbox/取り込み済み/` へ移ります。
3. **名前の確認**: 「候補を出す」で名前らしい語の一覧を出し、1語ずつ「人名／社名・店名・団体／名前じゃない／あとで」を決めて辞書に保存します。
4. **送る前の確認**: 3 に続けて、同じブラウザの画面のまま開きます（3 で出した候補を使うので、途中で読み込み直すと 3 からやり直しです）。「伏せて確かめる」で伏せたあとの全文を読み、気になる文は「さらに伏せる」。「全文を読んだ」に印を付けて「確認済みにする」。
5. **5欄を作る**: 読む役を有効にしていれば、確認済みの中身から進行メモを作ります。できたメモは画面で直して保存できます。
6. **確定する**: 「案件ファイル」で下書きの打ち合わせを確定します。確定したものは、「進行の状態」（今どこまで・次にやること・期限・次に動く側を手元AIが案にする）と「手元AIに聞く」の材料になります。
   - 架空データのモードでは、確定した打ち合わせは3〜5の画面に出なくなります。先に3〜5を済ませてから確定してください。
7. **共有フォルダに渡す**: 「進行の状態」で共有用の呼び名を決めると、進行メモを `<作業フォルダ>/share/進行メモ/`（架空データのモードでは `share-synthetic/`）に書き出せます。ほかの道具やエージェントに読ませるのは、このフォルダだけにしてください。

保存先のファイルは手で書き換えないでください（中身の指紋を持っていて、合わないと読み込みで止まります）。

## 読む役

環境変数 `SHOKOBAN_CLOUD_READER` で選びます。空のままなら止まっています。

- `claude`: Claude Code の `claude` コマンドを呼びます（`claude -p --model <モデル> --tools "" --output-format json`）。
  - `claude` に PATH が通っていて、ログイン済みであることが要ります。費用は利用者の契約によります。
  - `claude` は利用者自身の設定（CLAUDE.md・hooks・MCP など）を読み込みます。**外へつながる MCP や hooks を入れている場合、伏せたあとの文がそこにも渡り得ます。**
  - 失敗したときは終了コードしか表示されません（未ログイン・古い版・モデルが使えない、のどれでも同じ表示です）。
  - 呼ぶ回数は1か月 `SHOKOBAN_READER_MONTHLY_LIMIT` 回まで（既定 200）。
- `local`（試験的）: この PC の中の OpenAI 互換サーバー（`SHOKOBAN_READER_URL`、既定 `http://127.0.0.1:1234/v1`）に送ります。外のホストは断ります。
  - サーバーは自分で起動しておく必要があります。読む役への指示文だけで約7千字あり、打ち合わせ本文も足すので、**大きな文脈の長さ（数万トークン）**が要ります。例の `ctx: 8192` には収まりません。
  - 小さなモデルが指示どおりの JSON を返せるかは未確認です。返事の形が崩れると、空のメモになります。
- `fake`: 手元だけで決まった形を返す偽物（画面の試し用）。

## 手元AIを自動で止める

画面は手元AI（llama-server）を使う時に起動しますが、止めるのは別の小さなスクリプトです。`scripts/llm_idle_stop.py` を1分おきに動かすと、最後に使ってから `idle_minutes` を過ぎた llama-server を止めます（書庫番が起こしたものだけ）。macOS の見本は `deploy/macos-launchd/shokoban-llm-idle-stop.example.plist` にあります。これを入れない場合は、「手元AI」の画面の「手元AIを今すぐ止める」で止めてください（止めるまでメモリを使い続けます）。

画面を常駐させる見本は `deploy/macos-launchd/shokoban-gui.example.plist` です。

## 設定（環境変数）

| 名前 | 既定 | 意味 |
|---|---|---|
| `SHOKOBAN_WORK_DIR` | （必須） | 作業フォルダ（絶対パス）。この中の `runtime.json` を読みます |
| `SHOKOBAN_DATA_MODE` | （必須） | `real`（本番）か `synthetic`（架空） |
| `SHOKOBAN_REVIEW_REAL` | 空 | `1` で、本番データでも名前の確認・送る前の確認を開く |
| `SHOKOBAN_LLAMA_SERVER` | PATH 上の `llama-server` | llama-server の場所 |
| `SHOKOBAN_TAGGER_MODEL` | `gemma-4-12b-ja` | 手元AIの呼び名（`runtime.json` の `models` の名前） |
| `SHOKOBAN_CLOUD_READER` | 空（止める） | 読む役: `claude`／`local`／`fake` |
| `SHOKOBAN_CLAUDE_MODEL` | `opus` | `claude` のモデル |
| `SHOKOBAN_READER_URL` | `http://127.0.0.1:1234/v1` | `local` の送り先（この PC の中だけ受け付ける） |
| `SHOKOBAN_READER_MODEL` | なし | `local` のモデル名 |
| `SHOKOBAN_READER_MONTHLY_LIMIT` | `200` | 読む役を呼ぶ1か月の上限 |

## 既知の制約

- macOS 専用（Linux・Windows は上のとおり）。ポート 1234 は変えられません。
- llama-server の起動に失敗したとき、原因（引数・モデル・メモリ）が画面に出ません。
- 画面と指示文は日本語だけです。一部のエラー文は英語です。
- お客様の別名を登録する画面がありません（名前の辞書で補います）。
- 上限やしきい値（目立たせは1割まで、読む役の引用は120字まで、など）の多くはコードに決め打ちです。
- `pick_bench`・`mask_stage5`・`r3` など、モジュールの名前に開発中の呼び名が残っています。
